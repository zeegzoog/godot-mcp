# Security

- The bridge listens on `127.0.0.1` only, so other machines cannot reach it.
- Every command must carry a random token. The plugin writes it when the editor starts to `<user data dir>/godot-mcp/bridge-<port>.token` (the file and its folder are readable by your user only), and the server reads it from there. This also keeps web pages in your browser from driving the editor or reading the running game's output: a connection gets events only after it has sent the token, and one that sends a wrong token, or none within 5 seconds, is closed. The editor keeps at most 8 connections (each server keeps one). Both processes must therefore run as the same OS user. If they can't (containers, Flatpak, different users), set the same `GODOT_MCP_TOKEN` for both instead.
- `godot_create_script` only writes `.gd` files inside the project, never overwrites without `overwrite: true`, and accepts only plain identifiers for `class_name` and `extends_class`. Text you pass in `content` is written as given, never run by the tool; as with `godot_edit_script`, a `@tool` script runs in the editor once the editor loads it.
- `godot_read_script` and `godot_edit_script` work on existing `.gd` files inside the project only, change nothing but the one fragment you name, and never overwrite text you have typed in the editor and not saved. Your fragment is treated as plain text by the tools, never run by them. But code you put into a script is code: Godot runs a `@tool` script inside the editor as soon as it is saved, so editing one runs it with your authority.
- `godot_create_shader`, `godot_read_shader` and `godot_edit_shader` work on `.gdshader` and `.gdshaderinc` files inside the project only, never overwrite a file without `overwrite: true`, and never overwrite text you have typed in the shader editor and not saved. `godot_validate_shader` passes the shader path to Godot as data after `--`, never inside the check script.
- Node paths are resolved inside the edited scene only; the scene root can't be removed.
- `godot_game_call` runs only the methods you list in `permit`, and never one that can quit, evaluate code, call another method by name (`call`, `call_group`, `propagate_call`, `emit_signal`, `notification`, …), set a property by name (`set`, `set_deferred`, `set_indexed`) or free or replace a node (`free`, `queue_free`, `replace_by`, `create_instance`), including the thread-safe and thread-group variants (`call_thread_safe`, `set_deferred_thread_group`, `notify_thread_safe`, …). The game itself also refuses any engine method whose arguments name a method, a property or a notification to act on, unless it only reads, editor-only metadata (`set_meta` on a name starting with `_`), and calls or writes to the godot-mcp runtime node. `godot_game_set` refuses `script` and private names, including on a resource reached with `:`. Nothing `godot_game_set` changes is saved to disk.
- `godot_game_run_script` runs a `.gd` file of the project inside the running game with the game's full authority, as `godot_run_script` does in its own process: it is not limited by the refusals of `godot_game_call`, and code you put in the file is code. It takes a `res://` path only, never source text. Nothing it changes is saved unless the script saves it.
- `godot_run_project` `user_args` are placed after `--` and only for `mode: "process"`. A value that starts with `-` is a game argument, not a Godot engine option.
- `godot_run_project` `movie` writes its recording only inside the project or inside the folder you set with `GODOT_MCP_MOVIE_DIR`; the path is resolved and checked like any other file path, and only an absolute path, a whole number of frames and a frame rate reach the command line. It deletes an earlier recording at the same path (the `.avi`, or its numbered `.png` frames and `.wav`) only with `overwrite: true`.
- `godot_review_assets` and `godot_world_map` run a fixed script in a temporary Godot process that reads the checked request from a JSON file, so no argument reaches the command line or generated source. `godot_review_assets` writes nothing into the project; `godot_world_map` writes only the `.png` named by `output_path`, inside the project, and its `.json` beside it, replacing earlier files of those names.
- `godot_game_record` writes PNG files (and, with ffmpeg, one movie) only below the system temporary directory, never over an existing recording, and returns paths, not images.
- The authoring tools never replace an existing scene or resource. `godot_set_project_setting` accepts only a plain `section/path` key, escapes the value (also the strings inside an array or object), keeps the type of a setting that exists (a setting the engine does not define changes type only with `replace_type`), and writes every value, also a `value_text`, on one line, so it cannot add lines or sections to `project.godot`. A value text is parsed only when every constructor in it is a built-in type, so it never creates an Object or loads a Resource.

To report a vulnerability, follow [SECURITY.md](../SECURITY.md). Never open a public issue for it.
