# Tools

"Editor" means the tool needs a running Godot editor with the plugin enabled. "Running game" means a game started with `godot_run_project`, in the editor's Play mode or as a managed process. "Process run" means a managed process run, the one this server can debug.

`project_path` can be omitted when the server runs inside the project: tools then use the project open in the editor, else the first folder with a `project.godot` from the server's working directory upwards, else the only subfolder that has one (such as `app/`). A `project_path` you give always wins: when the open editor has another project, the tools that can work on files (reading and editing a script, creating a scene or a resource, project settings) use the files of the project you named and leave the editor alone, and an answer that changed something names the project directory.

Every tool takes only the parameters its schema lists (`additionalProperties: false`). A call with any other key does nothing and is refused with an error that names the unknown key and the accepted ones, so a misspelled or invented parameter is never dropped while the call reports success. A key set to `null` counts as absent.

| Tool | Needs | What it does |
| --- | --- | --- |
| `godot_get_version` | — | Engine version, from the editor or the Godot binary. |
| `godot_get_project_info` | Editor | Name, main scene, features and directory of the open project. |
| `godot_create_project` | — | Creates a minimal Godot 4 project at an absolute `project_path` with a display `name`, without needing an engine or editor. Preserves existing files and refuses to replace `project.godot`. Uses the Compatibility renderer; no main scene or bridge is installed. |
| `godot_launch_editor` | — | Launches the editor for `project_path`, or for the project the server runs in. |
| `godot_close_editor` | — | Closes the editor of `project_path` (else the project the server runs in) and answers once its process has exited. A connected editor quits without saving anything; when it has unsaved scenes or scripts it stays open and the answer lists them, unless `discard: true`. An editor that has another project open is never closed. Without a connected editor, only an editor this server started with `godot_launch_editor` can be stopped, by its PID, and only with `discard: true`. `timeout_seconds` (1–120, default 30) bounds the wait. |
| `godot_update_addon` | — | Installs or updates `res://addons/godot_mcp` in a project with the addon of this server's own build (it is built into the server), so both have the same version, and keeps the plugin enabled in `project.godot`. The old folder is replaced as a whole; files the new addon no longer has are removed. A connected editor of the project runs the old addon until it loads the plugin again, so the files are replaced under it only with `restart_editor: true`, which closes it (refused while scenes or scripts are unsaved, unless `discard: true`), installs and opens it again. Answers with `previous_version`, `version`, the added, updated and removed files and what the editor needs; nothing is written when the addon is already this version. When the editor's addon lacks a command a tool needs, the error names both versions and this call, and `godot_read_shader` / `godot_edit_shader` work on the shader file instead and say so. |
| `godot_run_project` | — | Plays the main scene or a given `res://` scene. With the editor, uses its Play mode. Without it (or with `mode: "process"`), starts a managed game with the remote debugger attached; `held: true` (process runs only) starts it held, for exact steps. `user_args` (process only) are strings the game reads with `OS.get_cmdline_user_args()`; they are placed after `--` and refused for editor Play and `mode: "auto"`. A source newer than its `.godot/imported` cache is reimported first when the editor has this project open, and otherwise the result names the paths and `godot_resave_resources`. `godot_stop_project` stops either one. |
| `godot_stop_project` | — | Stops what runs: the editor's Play mode when it plays and every managed process run, and lists what it stopped. With nothing running it says so and names the run that ended last; `recently_ended` lists how each earlier run ended. Pass `run_id` to stop one process run. |
| `godot_get_run_status` | — | Whether a scene is playing, and the managed process runs, each with its `user_args` and, once it has ended, its exit code, `signal`, `ended_by` (`server`, or `game` for anything else), `ended_at`, `how_ended` and `last_stderr`. Says that nothing is running when that is so, and how the last run ended. |
| `godot_get_open_scenes` | Editor | Open scene tabs and the active one. |
| `godot_open_scene` | Editor | Opens a scene by `res://` path. If that tab is already open and the file on disk has changed, reloads it and drops its undo history. A reload over unsaved editor changes, typed by hand or made by a tool, is refused unless you pass `discard: true`; `reload: true` reloads an open scene even when the file is unchanged. |
| `godot_save_scene` | Editor | Saves the active scene. Names in `scripts_saved` any open script tab with unsaved typing that the editor saved with it; clean scripts are not reformatted. |
| `godot_get_scene_tree` | Editor | Node hierarchy of the active scene, or of another open tab via `scene_path`. Paths are relative to the scene root. An instance node has `instance` and `editable_children`. |
| `godot_add_node` | Editor | Adds a node of any instantiable `Node` class or global script class, or an instance of a saved scene (`scene`), with optional initial `properties` (undoable); the answer lists each value as read back in `applied`, and a value Godot does not keep refuses the call. |
| `godot_remove_node` | Editor | Removes a node, restoring order and ownership on undo. A node an instanced scene brings is refused: Godot cannot save that deletion. |
| `godot_get_node_properties` | Editor | Reads a node's editor-visible properties as `{type, value}` in Godot's text format. `properties` reads only the names given, and `:` steps through a resource (`material_override:shader_parameter/glow_amount`). |
| `godot_set_node_properties` | Editor | Sets properties (undoable), converting values to the property's type: `[10, 20]` or `{"x": 10, "y": 20}` for vectors, `"#ff0000"` for colors, `res://` paths for resources. `:` steps through a resource built into the scene (`material_override:shader_parameter/glow_amount`) in the same undo action; a `.tres` file or another scene's resource is shared, so it is refused. The whole call is rejected if any property is unknown or unconvertible, or reads back differently from the value set (a setter that clamps or refuses it, or an audio `bus` the editor's AudioServer does not have, which Godot answers and saves as `Master`). A node inside an instance whose children are not editable is refused, because Godot would drop the change on save; `make_editable: true` (also on `godot_add_node`, `godot_attach_script`, `godot_connect_signal`) turns Editable Children on in the same undo action. |
| `godot_capture_viewport` | Editor with a window | Screenshot of the 2D or 3D editor viewport as PNG (`view`, `max_dimension` options). Switches the editor to that main screen; doesn't work with `--headless`. |
| `godot_review_assets` | Godot with a window | Renders a set of the project's scenes together in one PNG without writing a scene to the project, in a temporary Godot process (a small window: a headless Godot does not render). Without positions the assets stand in a row, `gap` apart. The light comes from a level scene (its WorldEnvironment and DirectionalLight3D nodes), an Environment resource plus `light`, or a neutral default; the camera is orthogonal or perspective with `yaw`, `pitch`, `size`/`fov`, fitted to the assets, or copied from a scene's Camera3D (`camera.scene`, `camera.node`); `planes` adds ground or water at a height. Answers each asset's bounds, its triangles, surfaces and mesh instances, and Godot's rendered primitives and draw calls with that asset alone, plus the totals of the picture. |
| `godot_world_map` | Godot with a window | A top-down map of a world split into many scene files (streamed zones), without running the game: the scenes from `dir` + `glob` (or `scenes`) stand at their saved transforms and are rendered with an orthographic camera in tiles, loading only the scenes that touch a tile, so memory stays bounded. `labels` draws each scene's bounds and file name faintly (red where collision or geometry is missing); `view: "collision"` draws the collision shapes instead, which shows holes in the ground. Answers `totals` and a `problems` list naming the scenes that lack collision or geometry first, then the map's world rect and scale, and a JPEG preview at most 1024 px on a side; `detail: "problems"` or `"scenes"` adds per scene its root, top-level children, bounds, collision bounds, mesh, collision and nested-scene counts, and `has_collision` / `has_geometry`, leaving out whole scenes past about 60000 characters. `output_path` writes the full-size PNG and the full JSON into the project and answers their paths instead of the preview. |
| `godot_create_scene` | — | Creates a `.tscn` with one root node (`root_type`, `root_name`) and opens it when the editor is connected. Without the editor it writes the file. Refuses to replace an existing scene. |
| `godot_attach_script` | Editor | Attaches a script to a node (undoable); an empty `script_path` detaches. The script must exist in the project. |
| `godot_connect_signal` | Editor | Connects a node's signal to a method inside the edited scene (undoable). The target must already have the method; a connection that exists is refused. |
| `godot_list_signals` | Editor | Signals of a node in the edited scene and what each is connected to. |
| `godot_create_resource` | — | Creates a `.tres` of a built-in `Resource` class. With the editor, Godot saves it; without it, an empty resource is written as text. Never replaces an existing file. |
| `godot_get_project_settings` | — | Reads project settings: live from the editor, else the entries stored in `project.godot`. Filter with `prefix`. |
| `godot_set_project_setting` | — | Sets one setting (`section/path`) to a string, number or boolean and saves it. A setting keeps its type: a value of another type is refused. The type is the stored one, else the engine's definition of the setting (a feature override such as `viewport_height.mobile` has the type of its base); with the editor the editor knows it, without the editor it comes from `project.godot` or from the engine, asked headless. With and without the editor a Color takes an HTML color such as `"#102b38"` or a name such as `"white"`, other types the text `project.godot` stores, such as `"Vector2i(1152, 648)"`; an Object text is refused. |
| `godot_get_input_map` | Editor | Lists the InputMap actions with their deadzone and events (`type` `key`, `mouse_button`, `joypad_button` or `joypad_motion`). Godot's built-in `ui_` actions are left out unless `include_builtin` is true. |
| `godot_edit_input_action` | Editor | Adds or removes events of one action (`add_events`, `remove_events`), sets its `deadzone`, creates it (`create: true`) or deletes it (`delete: true`), and saves `project.godot`. One undo step in the editor. All or nothing: an event to remove that the action lacks, or an unknown key name, changes nothing; an event already there is listed under `already_present`. Keys use the physical key by default (`physical: false` for the layout key). Built-in `ui_` actions can be edited but not deleted. |
| `godot_create_script` | — | Writes a `.gd` file into the project: the text you pass in `content`, then checked as `godot_validate_script` does (a script that does not validate is an error answer, and the file stays for `godot_edit_script`), or else an `extends` / `class_name` / `_ready()` template (`res://` path; the project is `project_path`, the editor's, or the one the server runs in). Refuses to overwrite unless `overwrite: true`. When the script is open in the editor, the overwrite is refused while its tab has unsaved changes and otherwise reloads the tab. Without the editor a `class_name` is registered in `.godot/global_script_class_cache.cfg` as the editor's scan would, so the next headless or process run knows the class. |
| `godot_read_script` | — | Reads an existing `.gd` script as the editor would save it: the editor's unsaved text when the script is open with unsaved changes (`dirty: true`), otherwise the file. Returns the text and a `version` label for it; `stale_tab: true` means an open tab still shows older text than the file, and `godot_resave_resources` with the path reloads it. Without the editor it reads the file. Scripts over 1 MiB are not handled. |
| `godot_edit_script` | — | Replaces one fragment of an existing `.gd` script: `old_text` must occur exactly once, and `new_text` takes its place. With the editor the change is one undoable action and the script is saved; it is refused while the script has unsaved changes in the editor (save or discard them, then read again). Pass the `version` from `godot_read_script` to refuse the edit if the script changed since. Without the editor the file is replaced as a whole and keeps its line endings, and a `class_name` the edit adds, renames or removes is updated in the class cache (`class_cache`, or `class_cache_warning` when it could not be). Never creates a file. |
| `godot_validate_script` | — | Checks a `.gd` file. When a language server is already running, lists its errors and warnings (`file:line:col`, code, message); a warning does not fail the check. Without one, `godot --headless --check-only` sees parse errors only and the answer says analyzer warnings were not checked. It also names classes the project declares but its class cache does not list yet; a script that uses one fails the check, because headless and process runs cannot find the class until `godot_resave_resources` or the editor registers it. |
| `godot_create_shader` | — | Writes a `.gdshader` or `.gdshaderinc` with the given `code`, as it is (tabs and line endings kept). Refuses an existing file unless `overwrite: true`. With the editor, the editor writes it: its shader in memory and the materials using it get the new code, an open shader tab is reloaded, and an overwrite is refused while that tab has unsaved changes. A new file gets a `.uid` file; an existing one keeps its uid. It does not compile the code: run `godot_validate_shader`. |
| `godot_read_shader` | — | Reads an existing `.gdshader` or `.gdshaderinc` as the editor would save it: the shader editor's unsaved text when the shader is open with unsaved changes (`dirty: true`), otherwise the file. Returns the text and a `version` label for it, as `godot_read_script` does. Without the editor it reads the file. |
| `godot_edit_shader` | — | Replaces one fragment of an existing `.gdshader` or `.gdshaderinc`: `old_text` must occur exactly once, and `new_text` takes its place. With the editor the shader is opened in the shader editor, the change is one undo step in its tab, the shader is saved and the materials using it get the new code; it is refused while the shader has unsaved changes in the editor. Pass the `version` from `godot_read_shader` to refuse the edit if the shader changed since. Without the editor the file is replaced as a whole, in the line endings it had. |
| `godot_validate_shader` | Godot binary | Compiles a saved `.gdshader` headless with Godot's own shader compiler (preprocessor, includes, syntax, types, identifiers and built-ins of its `shader_type`) and lists each error as `file:line: message`; an error inside an include names the include. Not checked: the GPU driver's compile of the generated code, shader-editor warnings such as unused uniforms, and unsaved editor text. A `.gdshaderinc` is checked through a shader that includes it. |
| `godot_run_script` | Godot binary | Runs an `extends SceneTree` script headless (`--path` project, `-s` script, `user_args` after `--`). Returns the exit code, stdout, stderr, and each `SCRIPT ERROR` with its file and line. `fixed_fps` (Godot's `--fixed-fps`) stops frames waiting for the clock, so a script that waits on `physics_frame` runs as fast as the CPU allows and counts the same frames: game time stays exact, and physics keeps the project's rate and delta. Whatever reads the wall clock no longer matches game time (`Time.get_ticks_msec`, `Time.get_unix_time_from_system`), and threads and background loads take the same real time while many more frames pass, so wait for their status, not for a frame count. `timeout_seconds` defaults to 120 (max 3600); on timeout the process tree is killed and stdout and stderr hold what it printed up to then. Lines arrive as printed, so a script that prints only at the end has nothing to return when killed: print each result as it is made. A project with `application/run/flush_stdout_on_print.debug=false` makes Godot buffer `print()`, which a kill loses and no flag overrides: `stdout_buffered` is true then, and `printerr()` still arrives. The answer holds the last 64 KiB of each stream, and one that outgrew that is kept whole (up to 256 MiB) in `.godot/godot-mcp`, named by `stdout_log` or `stderr_log`. A client that sends `_meta.progressToken` gets the newest output line in `notifications/progress` while the script runs. A `SCRIPT ERROR` that leaves the main loop idle (the process stays up, as an error in `_init` does) stops the run then, and the answer says so, instead of waiting out the timeout. A script that does not extend `SceneTree` or `MainLoop` is refused before Godot starts; a script Godot could not load (parse error, wrong base, missing file) is an error with `load_error`, even though Godot exits with code 0. Paths outside the project are refused. Headless Godot does not import, so before the script starts the files with a `.import` sidecar are compared with their `.godot/imported` cache: an editor open on the project reimports the stale ones first, otherwise the script still runs and `import_warning` lists them and names `godot_resave_resources` (`stale_imports` holds the first 20 paths, the total and whether they were reimported). Headless Godot saves a `.tscn`/`.tres` without `uid://` references and with `null` for every shader uniform the script never set; the server writes the uids back and removes those lines afterwards (`resource_repairs`). A binary `.scn`/`.res` (compressed or not) loses its header uid the same way; Godot's `ResourceSaver.set_uid` writes the old one back (a new one for a file that had none), listed in `resource_repairs` too, and an editor open on the project refreshes every scene, resource, script and shader the script wrote and reloads the ones it has loaded (`editor_refresh`), so a material sees a rewritten shader's new uniforms and defaults. The summary counts the repairs and names at most three files; `resource_repairs` and each `editor_refresh` list stop at 20 entries, with the full count beside them (`resource_repairs_total`, `<list>_total`). `resource_damage` names what a file the server could not write still lacks. |
| `godot_delete_file` | — | Deletes project files (`paths`, up to 64) with their `.uid`, `.import` and `.godot/imported` data. Refuses a file another project file still names by `res://` path or `uid://` unless `force: true`, and lists those `references` with a `kind`: `written` when a `.gd` script only writes the file (`ResourceSaver.save`, `FileAccess.open` for writing, `DirAccess` removal), which does not refuse it, `used` otherwise; refuses `project.godot`, `.godot/`, the Godot MCP addon, a `.uid`/`.import` whose file exists, and directories (an empty one with `allow_empty_dir: true`). All or nothing: while any path is `refused`, nothing is deleted. With the editor, open scene and script tabs of the files are closed (a tab with unsaved changes is refused), the FileSystem dock is updated and the files go to the system trash unless `trash: false`. Without the editor the files are deleted permanently and `rescan_needed` is true. `dry_run: true` only reports. |
| `godot_resave_resources` | — | Refreshes the given `res://` files after external edits. With the editor, assets it already knows are re-imported synchronously and other files are re-scanned; an open script tab without unsaved changes is reloaded from its file (`reloaded_tabs`), and one with unsaved changes is kept (`unsaved_tabs`). A shader, shader include or resource the editor has loaded, and a loaded script without a tab, is reloaded in place from its file (`reloaded_resources`), so a material sees a rewritten shader's new uniforms. A path it has never scanned is scanned first and listed under `reimported` only once a `.import` file exists; otherwise it is `not_scanned`. Without paths, rescans the whole project in the background. `wait: true` returns only after scanning and importing finish (up to 60s) and reports how many files were imported. Without the editor, runs `godot --headless --path <project> --import` and lists every source it imported under `imported`, with its `kind` (the importer: `scene`, `texture`…) and `type`. A requested path whose `.godot/imported` data still does not match the source's bytes is listed under `still_stale` with a `reason`, and the call is an error: Godot's scan skips a source rewritten within the second its last scan saw. `force: true` makes the headless import reimport the given paths whatever Godot's cache says (`forced`). |
| `godot_list_export_presets` | Godot binary | Lists the presets in `export_presets.cfg`, read by Godot's own `ConfigFile`: name, platform, `export_path`, filters, custom features and every stored option (`binary_format/architecture`, `texture_format/etc2_astc`...). An option the preset never stored is absent and takes the platform's default. |
| `godot_set_export_preset` | Godot binary | Creates a preset (`create: true` with `platform`) or changes one through Godot's `ConfigFile`, the way the Export dialog stores it: `export_path`, `include_filter`, `exclude_filter`, `custom_features` and `options`. Only what is given changes; an option keeps its type. `new_options` lists names that were not stored before, since Godot ignores an option its platform does not have. Refused while the editor has the project open (it writes its own copy back); close it with `godot_close_editor` first. |
| `godot_get_import_params` | — | Reads a file's import parameters, the `[params]` of its `.import` sidecar that the Import dock shows: `importer`, the imported `type`, `params` and each option's Godot type under `types`. From the editor when it has the project open, else with the Godot binary. A file with no `.import` yet is refused; import it with `godot_resave_resources` first. |
| `godot_set_import_params` | — | Changes import parameters the way the Import dock does and reimports the file: `params` (such as `{"compress/mode": 2, "compress/high_quality": true}`) are set after copying every parameter of `copy_from`'s `.import` (same importer only). An option keeps its type. With the editor the change goes through its file system, so the dock and the loaded resource follow; without it Godot's `ConfigFile` edits the file and `godot --headless --import` reimports. `new_options` lists names the file did not hold before and `ignored_options` the ones the importer dropped on reimport (a typo or another importer's option). Nothing changed means no reimport; `reimport: false` only edits the file. `importer` switches the importer as the dock's "Import As" does (`3d_texture` with `slices/horizontal` turns a PNG strip into a `Texture3D`): the new importer starts from its defaults, the name is checked against Godot's importers for the file type, and the answer gives `importer`, `previous_importer` and the imported `type`; an importer Godot does not have for the file is an error, not a silent fallback. |
| `godot_export_project` | Godot editor binary | Exports with a preset, headless: `mode` `pack` (default, `--export-pack`, a `.pck` or `.zip`, no template needed), `release` (`--export-release`) or `debug` (`--export-debug`), after `godot --headless --import` (skipped with `import: false`, or while the editor has the project open). `output_path` defaults to the preset's `export_path` and must stay inside the project. Returns `ok`, `output_path`, `size_bytes`, `exit_code`, `duration_seconds`, the `ERROR`/`WARNING` lines and the end of the log. A missing preset, a missing export template, a failed import, no file written or a timeout (`timeout_seconds`, default 600) is an error with that log. See [Exporting](#exporting). |
| `godot_run_output` | Running game | Logs, warnings and errors, with stack traces, from a managed process run or the editor's running game (`since`, `level`). |
| `godot_game_tree` | Running game | Live nodes of the running game: path, class, position, visible text. Filter by `name`, `class`, `group` or `text`. |
| `godot_game_get` | Running game | A live node's properties, groups and, optionally, signals and methods. `/` reads a Dictionary key or an Object property (get only; private names are refused). A missing segment is that property's entry in `property_errors` and names the segment; other properties are still returned. `null` is a value that really is null. `:` steps through a Resource (`material:shader_parameter/caustics`), including a name that starts with `_`. A requested `script` is omitted. A non-resource `:` step names the `/` form. |
| `godot_game_set` | Running game | Sets properties on a live node. `/` writes an Object field or a Dictionary key; an unknown property is an error that names the segment. `:` steps through a Resource. A `res://` path assigns a saved resource to an Object property. Refuses `script`, private names, and a Node in the middle of a `/` path. Nothing is saved to disk. |
| `godot_game_call` | Running game | Calls one method on a live node. The method must be listed in `permit`; methods that can quit, evaluate code, call other methods by name, set properties by name or free or replace the node are refused. A JSON string is passed as a `StringName` or a `NodePath` where the method asks for one. When the method takes the node out of the tree (it reloads or changes the scene), the answer has `left_tree: true` and the path the node had before the call. |
| `godot_game_signals` | Running game | A live node's signals and their connections. |
| `godot_game_observe` | Running game | Watches signals for a few frames, returns the ones that fired, then disconnects. |
| `godot_game_snapshot` | Running game | Scene path, monotonic `scene_generation`, `scene_instance_id`, frame, pause flag, children, and the loaded root script path plus its SHA-256. |
| `godot_game_state` | Running game | Reads the states the project's own adapter script registered for its game (the run, the level, the balls...), by name; with no names it reads all of them and lists the adapter's commands with their help. See [The project adapter](running-game.md#the-project-adapter). |
| `godot_game_command` | Running game | Runs one command the project's adapter registered, by name, with a dictionary of arguments. The command does what the project wrote, files included. See [The project adapter](running-game.md#the-project-adapter). |
| `godot_game_input` | Running game | Injects key, text, mouse, touch and gamepad input, and waits, as a sequence of steps. Pointer coordinates are in `coordinate_space`: `viewport` (default) is pixels of the root viewport's visible rectangle (what `_input` sees after content scale), `window` is pixels of the game window; neither is a screen or world pixel. The answer names the space and the mapping between the two, and `click_node` returns the point it clicked. A touch step also emits the engine's emulated mouse event first (`device` `DEVICE_ID_EMULATION`, same position) when `emulate_mouse_from_touch` is on; `emulate_mouse: false` turns that off for the call and restores it afterwards. Gestures: `click`, `swipe`, `path` (press, drag through points, release; at most 600 frames), `circle` (that drag around a center) and `click_node` (the center of a Control, Node2D or Node3D). More than 20 steps return `ok_count` and `failed` unless `verbose` is true. `time_scale` sets `Engine.time_scale`. A step that fails releases everything the server still holds. Mouse steps are Godot events and leave the OS cursor in place unless `warp_mouse` is true. |
| `godot_game_input_release` | Running game | Releases every key, button, axis and touch this server still holds down. |
| `godot_game_wait` | Running game | Waits for process frames, for a node to exist (`node`), for a signal (`node` and `signal`), for a public property (`property`, `op`, `value`), or for a newer `scene_generation`. A missing `/` segment is an error that names it, not a timeout; `null` means the value is null. `timeout` is in frames. `time_scale` (0 to 8) sets `Engine.time_scale`; the runtime restores the previous value when the game exits. |
| `godot_game_physics` | Running game | Controls game time. `hold` stops the game at the start of a physics tick; while held, `step` runs an exact number of ticks (or until a condition holds), input is applied by tick, and `resume` lets the game run. Without a hold, `step` advances N engine physics iterations and leaves the tree paused. See [Holding a game](running-game.md#holding-a-game). |
| `godot_game_scenario` | Running game | Plays one input sequence in a held managed game: Input Map actions and pointers, a known number of physics ticks per step, then `CharacterBody` and property snapshots, warnings, errors and an optional screenshot. Releases all input when it ends. See [Playing a scenario](running-game.md#playing-a-scenario). |
| `godot_game_run_script` | Running game | Runs one function of a `.gd` file inside the running game, against the live scene, so a heavy scene stays loaded between test scripts. ## Exporting

The export tools run the Godot binary named by `GODOT_PATH`, headless; it must be an editor build. Presets live in `export_presets.cfg`, which Godot reads and writes (its `ConfigFile`), so a preset made here is the same as one made in Project > Export.

```jsonc
// A Linux preset for a 32-bit ARM device whose GPU has ETC2/ASTC but no S3TC.
{"name": "webOS", "create": true, "platform": "Linux", "export_path": "build/game.pck",
 "options": {"binary_format/architecture": "arm32",
             "texture_format/etc2_astc": true, "texture_format/s3tc_bptc": false}}
// godot_export_project
{"preset": "webOS", "mode": "pack"}
```

A pack holds the project data only; run it with a matching engine binary (`godot --main-pack game.pck`). `release` and `debug` also need the export templates of this exact Godot version, or the preset's `custom_template/release` / `custom_template/debug` option pointing at a template binary. The output must stay inside the project; copy it elsewhere afterwards. The import before the export uses the same `timeout_seconds`.

## Feedback to the maintainers

While it works, the AI can note what is missing, broken or misleading in godot-mcp itself: a tool that fails for no clear reason, a capability no tool offers, a description that is wrong. When your request is done, it builds one report and shows it to you. You decide what happens next:

- **Copy it** and open an issue yourself, or open the prefilled new-issue link the AI gives you.
- **Let the AI submit it.** It publishes the issue through your own signed-in [GitHub CLI](https://cli.github.com) (`gh auth login`), under your GitHub account. This needs your explicit yes in the conversation.
- **Discard it.**

What is recorded: the AI's own notes, and from the server only the versions (server, addon, Godot), platform, whether the editor was reachable, the first line of recent failures of the tools a note names, and the names of tools the AI asked for that do not exist. Never gathered: project name, scene, script or resource contents, screenshots, environment values, the bridge token. Everything stays in memory until you approve a submission, and absolute paths, tokens and `@mentions` are removed from the text. The report will be public, so read it before you agree; the redaction is a safety net, not a guarantee.

To tighten it, set `GODOT_MCP_FEEDBACK=draft` (the AI can write reports but has no way to send one) or `off` (the feature does not exist). If your MCP client lets you pre-approve tools, do not pre-approve `godot_submit_feedback`: a per-call prompt is the only check outside the AI's own judgement.
